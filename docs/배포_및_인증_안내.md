# GitHub Pages 배포 및 Google 인증 안내

## 1. 상태와 전제

이 프로젝트는 빌드 없는 정적 사이트입니다. 파일 작성이나 로컬 점검만으로 인터넷에 배포되지는 않습니다. 저장소 생성, Pages 설정, 배포 성공 및 실제 HTTPS 응답을 각각 확인해야 합니다.

브랜드는 **Future Soul Games**, 법적 사업자는 **꿈모아 (DreamMoa)** 입니다. Search Console은 사이트 소유권 확인 수단이며 Play Console 조직 계정의 다른 심사 요건을 대신하지 않습니다.

## 2. 계정과 주소 확인

1. GitHub에 직접 로그인합니다. 계정이 없다면 사용자가 직접 생성합니다. 계정 비밀번호나 인증 코드를 채팅이나 파일로 공유하지 않습니다.
2. 프로필의 실제 사용자명을 확인합니다. `futuresoulgames` 계정/조직을 소유하거나 관리할 권한이 있는 경우에만 목표 루트 주소를 사용할 수 있습니다. 공개 프로필이 없다고 해도 사용자명 확보를 보장하지 않습니다.
3. 해당 소유자 아래 공개 저장소 `<실제사용자명>.github.io`를 만듭니다. 목표 계정이면 `futuresoulgames.github.io`입니다. 기존 저장소가 있으면 먼저 내용을 확인하고 병합합니다.

Google 소셜 로그인에서 본인 확인이 거절되면, 기존 GitHub 아이디·비밀번호 로그인 또는 평소 Google에 로그인하던 지원 브라우저를 사용합니다. 보안 확인을 우회하지 않습니다.

## 3. 업로드 및 Pages 설정

### 방법 A: GitHub 웹 화면

1. 빈 저장소에 `index.html`, `privacy.html`, `404.html`, `assets` 폴더를 업로드합니다.
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch → main / (root)**를 선택하면 빌드 도구 없이 배포할 수 있습니다.
3. 이 방법에서 README/안내서까지 올리면 직접 URL로 접근될 수 있습니다. 안내서에는 비밀정보를 넣지 않습니다. 모든 관리 파일과 점으로 시작하는 파일까지 보존하려면 아래 Git 방법을 권장합니다.

### 방법 B: Git 및 GitHub Actions — 준비된 워크플로

프로젝트 디렉터리에서 실행합니다. `YOUR_ACCOUNT`는 실제 계정명으로 바꾸세요. 기존 원격 저장소에 파일이 있다면 먼저 clone하여 병합하고 강제 push하지 마세요.

```powershell
cd E:\12_UnityProjects\FutureSoulGames
git init -b main
git add .
git commit -m "Create Future Soul Games official website"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_ACCOUNT.github.io.git
git push -u origin main
```

Git이 인증을 요구하면 공식 로그인 창에서 직접 진행합니다. 커밋 이름/이메일을 요구하면 자신의 공개용 GitHub 이름 및 GitHub noreply 이메일을 저장소 범위에서 설정합니다. 개인 실명/비공개 이메일을 임의로 커밋 작성자에 넣지 마세요.

저장소의 **Settings → Pages → Source: GitHub Actions**를 선택한 뒤 **Actions → Deploy GitHub Pages → Run workflow → main**을 실행합니다. 이후 main push는 자동 배포됩니다. Actions가 금지된 계정/저장소라면 정책 확인 또는 방법 A를 선택합니다. 두 배포 방식을 동시에 혼용하지 마세요.

워크플로는 검사 후 `_site`에 공개 파일만 모아 Pages 아티팩트로 배포합니다. Node 설치/npm install은 필요 없습니다. Pages 환경 배포 승인이 정책상 필요하면 소유자가 승인해야 합니다.

## 4. 배포 검증

- Actions 배포 작업의 성공 여부를 확인하고 **Settings → Pages**에 표시되는 실제 URL을 엽니다.
- 사용자 사이트라면 `https://YOUR_ACCOUNT.github.io/`입니다. 다른 이름의 프로젝트 저장소는 `/저장소명/` 경로가 붙습니다. 이 프로젝트의 `404.html`은 사용자 사이트 루트용이므로 프로젝트 저장소라면 해당 링크와 CSS 경로를 배포 접두 경로에 맞추세요.
- HTTPS와 정상 응답을 확인합니다. **Enforce HTTPS** 옵션이 표시되면 활성 상태를 확인합니다.
- Home/Games/About/Contact 이동, 이메일 링크, Privacy Policy 이동·복귀를 확인합니다.
- 모바일 폭 320px·390px와 PC 폭에서 가로 스크롤, 글자 잘림, 겹침이 없는지 확인합니다.
- 소스 보기에서 법적 명칭, 개인정보, 인증 태그를 확인합니다.
- 확인 결과를 `docs/검증_상태.md`에 기록합니다.

## 5. Search Console HTML 태그 인증

1. 실제 배포 URL을 확보한 다음 https://search.google.com/search-console 에 소유권을 보유할 Google 계정으로 로그인합니다.
2. **속성 추가 → URL 접두어**를 선택하고 실제 HTTPS 홈페이지 URL을 입력합니다. `github.io` 전체 도메인의 DNS를 관리할 수 없으므로 도메인 속성 DNS 인증을 선택하지 않습니다.
3. **HTML 태그** 방법에서 발급된 메타 태그 전체를 복사합니다.
4. `index.html`의 `<head>` 안 `SEARCH_CONSOLE_VERIFICATION` 주석 바로 다음 줄에 실제 태그를 넣습니다. JavaScript로 삽입하거나 본문에 넣지 않습니다. 예시 값을 인증 값으로 사용하지 않습니다.
5. `node tools/check.mjs`로 점검하고 commit/push합니다. Actions/Pages 배포 성공을 확인합니다.
6. 로그인하지 않은 상태로 실제 홈페이지의 페이지 소스를 열어 `google-site-verification`의 **활성 메타 태그와 실제 content**가 head에 남아 있는지 확인합니다. 동적 DOM만 확인하는 것으로 대체하지 않습니다.
7. Search Console에서 **확인**을 누르고 소유권 확인 성공을 확인합니다. 인증 후에도 메타 태그를 유지합니다.
8. Play Console 조직 계정의 웹사이트 주소에 정확히 같은 URL을 입력하고 해당 화면의 웹사이트 소유권 확인 절차를 진행합니다. Google 계정 간 권한 연결 및 추가 심사는 화면 안내에 따릅니다.

실제 Google 인증 코드를 전달하면 index.html 삽입부터 재배포까지 이어서 진행할 수 있습니다. 인증용 메타 값은 공개 HTML에 남는 값입니다. 계정 비밀번호, OTP, API 토큰은 전달하지 않습니다.

## 6. 개인정보처리방침 검토

`privacy.html`은 홈페이지 전용 초안입니다. 현재 구현에는 분석 도구·광고·로그인·입력 폼·외부 폰트가 없습니다. 이메일 문의에는 Gmail을, 공개 호스팅에는 GitHub Pages를 사용한다는 구성을 반영했습니다. 운영자가 실제로 문의를 처리·삭제하는 방식과 방침을 일치시킨 뒤 공개 상태를 유지하세요. 게임에서 수집하는 정보는 게임별 정책으로 별도 관리합니다.

## 7. app-ads.txt와 향후 변경

현재는 광고 게시자 ID와 app-ads.txt를 만들지 않습니다. 추후 실제 소유 도메인, AdMob에 등록한 개발자 웹사이트, 크롤러의 최상위 도메인 판정 조건을 확인한 후 게시합니다. `github.io` 주소에서의 Pages 배포 및 Search Console 인증만으로 AdMob app-ads.txt 인증 완료를 보장하지 않습니다.

자체 도메인을 확보하면 Pages의 도메인/DNS/HTTPS 설정을 확인하고 실제 AdMob 제공 행을 사이트 최상위 `app-ads.txt`에 넣습니다. Actions 워크플로의 복사 목록에도 해당 파일을 추가해야 합니다. 현재 도메인을 구매하거나 임의의 CNAME 파일을 만들 필요는 없습니다.
